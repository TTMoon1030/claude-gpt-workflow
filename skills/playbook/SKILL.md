# 照團隊的做法做事（playbook）

VT 團隊每一件業務工作都有一份寫好的做法，放在小鎮上，連上小鎮的 Claude 才讀得到。你的工作是先讀做法，再照著做，不要用自己習慣的格式。

## 一、判斷是哪一件事

| 使用者說的 | 代號 |
|---|---|
| 開發名單、找名單、找品牌 | `list` |
| 開發信、陌開信、陌生開發 | `cold` |
| 活動報名確認信、出席確認 | `invite` |
| Demo 前研究、品牌研究、會前研究 | `research` |
| 做簡報、提案簡報、投影片 | `deck` |
| 會後整理、整理會議、會後信 | `meeting` |
| log hubspot、記到 HubSpot | `hubspot`（照 hubspot 技能做，格式以做法為準） |
| 報價單 | `quote` |
| 走期表、導入時程 | `timeline` |
| 客戶交接表 | `handover` |

對不上任何一件，就照一般方式幫忙，不用硬套。

## 二、拿做法

用 `vt-workshop` 連線的 `playbook` 工具，`task` 帶代號呼叫一次，共同規則和那件事的做法會一起回來。工具清單上沒看到，先搜尋工具一次（名稱裡有 vt-workshop 和 playbook）。

**找不到這個工具**，代表這台電腦的 Claude 還沒連上小鎮：

1. 照 hub 技能（`<外掛>/skills/hub/SKILL.md`）的「連接工作台」做，瀏覽器跳出來時請使用者按允許。
2. 連好之後，這段對話的工具清單不會自己更新：請使用者開一段新對話，把剛才要做的事再說一次。
3. 連不上：請使用者到小鎮的外掛更新站按「一鍵更新」。

做法沒讀到之前不要先做，也不要用一般的格式頂替。

`<外掛>`＝這份 SKILL.md 所在資料夾的上上一層。

## 三、照做法做

1. 兩份都讀完再動手。兩份有出入時，以那件事的做法為準。
2. 做法裡「開始前」要問的事，一次問完。
3. 照步驟做，交出去之前跑一次做法裡的檢查清單。
4. 照做法的「交付」那一段回覆。

## 做法暫時讀不到的時候

工具有、但回覆說做法暫時讀不到：告訴使用者，請他等一下再試。使用者說不等了，才照一般方式做，並說清楚這次不是照團隊的格式。
