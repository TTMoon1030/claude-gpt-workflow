# 整理舊版設定

`<外掛>`＝有 `scripts/` 資料夾的那一層，也就是這份 SKILL.md 所在資料夾的上上一層（從 GitHub 安裝的是 `…/gpt-workflow/<版本>/`）；`<Codex>` 是 `bash "<外掛>/scripts/find_codex.sh"` 印出的路徑；`<DB>` 是第 2 步決定沿用的資料庫。

原則：
- 不刪除任何檔案。要清掉的東西一律搬到備份資料夾 `<DB>/_to_delete/舊版設定_<今天日期 YYYYMMDD>/`：資料庫裡的東西照原本的相對位置放（例如 `_scripts/generate_image.py` → `<備份>/_scripts/generate_image.py`），資料庫外面的放 `<備份>/外部/`，並保留它相對於家目錄的路徑（例如 `~/.claude/skills/gpt-image` → `<備份>/外部/.claude/skills/gpt-image`），這樣不會同名互蓋。
- 直接修改的檔案（README_索引.md、MEMORY.md、記憶檔、終端機設定檔），改之前先照上面的路徑規則複製一份原檔到備份資料夾。CLAUDE.md 不用自己備份，build_db.sh 改之前會自動把原檔放到 `<DB>/_to_delete/CLAUDE_修改前_<時間>.md`。
- 空資料夾：搬走東西後，上層資料夾如果變空、而且不是標準位置，就跟著一起搬（例如放空殼資料庫的資料夾）。`~/.claude/skills/`、資料庫裡的 01–06、`_scripts/`、`_to_delete/` 這些標準資料夾就算空了也不要動。
- 全部做完在備份資料夾寫一份 `說明.md`：每一項原本在哪裡、為什麼搬或改、怎麼還原；有隱藏檔（名稱開頭是 `.`）就註明在 Finder 按 ⌘⇧. 才看得到。
- 第 1 步用一張表一次問完使用者的決定；使用者回覆後就照決定做，不用每一類再問一次。使用者說不要的那一類就跳過。
- 不顯示 API 金鑰的內容。

1. **掃描**：執行 `bash "<外掛>/scripts/scan_legacy.sh"`。總結是「沒有找到舊版留下的東西」就結束這個技能。找到東西就用表格白話說明：找到什麼、在哪裡、建議怎麼處理（照下面各段），一次問完使用者的決定。
2. **選資料庫**（類別「資料庫」）：
   - 只有一個：沿用它，當作 `<DB>`。
   - 有好幾個：建議沿用「自己的檔案」最多的那個（一樣多時選名稱是「我的業務資料庫」的），請使用者確認。其他的：自己的檔案 0 個的空殼，問使用者後整個搬到備份資料夾的 `外部/`；有檔案的不要自動合併，列出裡面的檔案，問使用者要不要搬進 `<DB>` 對應的資料夾。
   - CLAUDE.md 是「舊版規則包（工作規則）」：建議保留，它本來就有生圖做法；build_db.sh 會更新失效的 Codex 位置，並在最後補一小段「用外掛生圖、不要用 API」。使用者想換新版的話，先說明新版會少掉舊檔裡的做事規則（簡報、畫面、用字、交付）、主動上網查資料和發成連結那幾段，確認後再把舊的搬到備份資料夾。
   - 執行 `bash "<外掛>/scripts/build_db.sh" "<DB>"`：補齊缺少的資料夾；沒有索引就建；CLAUDE.md 沒有生圖做法就補上；Codex 位置失效就更新。原有檔案不會被覆蓋。
   - 「放錯位置的設定檔」（桌面或文件最上層的 CLAUDE.md、README_索引.md）：問使用者後搬到備份資料夾的 `外部/`。
3. **OpenAI API 生圖的遺留**：
   - 「OpenAI API 腳本」「Python 環境」：搬到備份資料夾（README_索引.md 裡提到它們的行，第 7 步一起處理）。
   - 「API 金鑰檔」：搬到備份資料夾，並提醒使用者：這把金鑰如果是為了生圖才申請的，可以到 https://platform.openai.com/api-keys 停用。
   - 「終端機設定」：先把那個檔案複製一份到備份資料夾的 `外部/`，再在那一行最前面加上 `# ` 停用，不要刪掉整行。改完提醒使用者，要等終端機或 Claude 重開才會生效。
   - 「Codex 登入方式」是 API 金鑰：在背景執行 `"<Codex>" login --device-auth` 改用 ChatGPT 登入，把網址和代碼給使用者。
4. **舊技能**：
   - 「舊技能（本機）」：整個資料夾搬到備份資料夾的 `外部/`。
   - 「舊技能（帳號上傳）」：要使用者自己關。請他到 Claude 左側「自訂」→「技能」，找到舊的 gpt-image，關掉或刪除。不要去動 Application Support 裡的檔案。
5. **Claude 記憶**：給使用者看掃描列出的那幾行，問要不要修正。整份都在講用 API 生圖的記憶檔，搬到備份資料夾的 `外部/`；只有幾行提到的，把那幾行改成「生圖用 gpt-workflow 外掛（Codex，ChatGPT 登入），不要用 OpenAI API」。MEMORY.md 是記憶的目錄，跟著它指向的記憶檔處理：記憶檔搬走就刪掉指向它的那一行，記憶檔改寫就把那一行的說明一起改。
6. **不用處理**：「Codex」（其他幾份 Codex 不影響，外掛會優先用桌面版內建的那份）和「其他外掛」（OpenAI 的 Codex 外掛）。在表格裡寫「不用處理」就好。
7. **更新索引**：先備份 `<DB>/README_索引.md`，再：刪掉指向已搬走檔案的行；在檔案清單加一行「- `_to_delete/舊版設定_<日期>/` — 整理舊版教學設定時搬出來的東西，怎麼還原見裡面的 說明.md」。舊索引缺「資料夾結構」或「命名規則」段的話，從 `<外掛>/templates/README_索引.md` 補上（資料夾結構放在檔案清單前面，命名規則放最後），原本的檔案清單保留。
8. **確認**：再跑一次 `scan_legacy.sh`。剩下的應該只有沿用的資料庫、使用者選擇保留的項目、「不用處理」的項目，以及使用者還沒去關的帳號上傳舊技能（關掉後就不會再列出）。用表格回報每一項做了什麼、備份放在哪裡；搬走東西後留下的空資料夾也提一句，問使用者要不要一起搬到備份。
